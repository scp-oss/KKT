# kkt-monitor

Сервис учёта ККТ (контрольно-кассовой техники): реестр касс, загрузка CSV-выгрузок
«Мониторинг ККТ и ФН» и уведомления в Telegram об истечении сроков.

Написан на Go, база — встроенный SQLite (без cgo), весь UI и статика собраны в один
бинарник. Можно запускать в Docker или как обычный исполняемый файл, без контейнера.

## Возможности

- Веб-форма (за паролем) для загрузки CSV-выгрузки. Записи уникальны по полю
  **Заводской номер ККТ** — при повторной загрузке существующие обновляются,
  новые добавляются.
- Хранятся поля: Регистрационный номер ККТ, Заводской номер ФН, Заводской номер
  ККТ, Адрес расчетов, Дата окончания оказания услуг (ОФД), Модель ККТ, Дата
  окончания срока ФН.
- Реестр ККТ с подсветкой записей, у которых истекает срок услуг ОФД или срок ФН.
- Уведомления в Telegram за **30, 10, 5, 2 и 1 день** до окончания срока — отдельно
  по дате окончания услуг ОФД и по дате окончания срока ФН.
- Несколько получателей уведомлений (по chat_id), каждого можно включить/отключить.
- Бот может слать сообщения напрямую в api.telegram.org либо через свой
  relay/зеркало (например, `https://your-domain.tld/bot{TOKEN}/sendMessage?auth={AUTH_KEY}`),
  опционально через SOCKS5-прокси.
- Настройки бота и загрузка CSV доступны только после входа по паролю; секретные
  значения (токен, auth_key, адрес relay, пароль SOCKS5) не отображаются повторно
  в форме — сохраняются только через сервер, поле остаётся пустым до перезаписи.

## Быстрый старт без Docker

Нужен Go 1.25+.

```bash
cp .env.example .env
# отредактируйте .env — задайте ADMIN_PASSWORD

export $(grep -v '^#' .env | xargs)
go run .
```

Сервис поднимется на `http://localhost:8080`. База SQLite создастся автоматически
по пути `DB_PATH` (по умолчанию `data/kkt.db`).

Сборка отдельного бинарника:

```bash
go build -o kkt-monitor .
ADMIN_PASSWORD=... ./kkt-monitor
```

## Запуск в Docker

```bash
cp .env.example .env
# отредактируйте .env

docker compose up -d --build
```

Данные (SQLite) сохраняются в volume `kkt-data`, переживают пересборку контейнера.

Либо без compose:

```bash
docker build -t kkt-monitor .
docker run -d --name kkt-monitor \
  -p 8080:8080 \
  -e ADMIN_PASSWORD=change-me \
  -v kkt-data:/data \
  kkt-monitor
```

## Переменные окружения

| Переменная      | По умолчанию   | Описание                                              |
|-----------------|----------------|--------------------------------------------------------|
| `ADMIN_PASSWORD`| —              | Обязателен. Пароль для входа в веб-интерфейс.           |
| `LISTEN_ADDR`   | `:8080`        | Адрес, на котором слушает HTTP-сервер.                  |
| `DB_PATH`       | `data/kkt.db`  | Путь к файлу базы SQLite.                               |
| `COOKIE_SECURE` | `true`         | Флаг Secure для cookie сессии; `false` — только для HTTP без TLS. |

## Настройка Telegram-бота

Все настройки бота задаются в веб-интерфейсе (`/settings`), а не через переменные
окружения — чтобы адрес relay/токен нигде не «светился» в открытом виде.

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. В `/settings` выберите способ отправки:
   - **Напрямую** — сообщения идут прямо в `api.telegram.org`.
   - **Через свой relay/прокси-адрес** — укажите шаблон адреса с плейсхолдерами
     `{TOKEN}` и `{AUTH_KEY}`, например:
     `https://your-domain.tld/bot{TOKEN}/sendMessage?auth={AUTH_KEY}`
3. При необходимости включите отправку через SOCKS5-прокси и укажите его адрес
   (`host:port`) и, если нужно, логин/пароль.
4. Добавьте получателей — их Telegram chat_id (узнать свой chat_id можно у бота
   [@userinfobot](https://t.me/userinfobot)).
5. Нажмите «Отправить тестовое сообщение», чтобы проверить настройки.

Уведомления рассылаются автоматически: фоновый планировщик проверяет реестр
каждый час и отправляет сообщение всем активным получателям ровно один раз при
достижении порогов 30, 10, 5, 2 и 1 день до `Дата окончания оказания услуг` и
до `Дата окончания срока ФН`. Повторная загрузка CSV с новой датой (например,
после продления) снова включает отсчёт порогов для этой записи.

## Формат CSV

Ожидается выгрузка «Мониторинг ККТ и ФН» — разделитель `;`, значения ячеек в
формате `="значение"`, кодировка UTF-8 (с BOM или без). Колонки определяются по
заголовку, поэтому порядок столбцов в файле не важен — важны только их названия.
